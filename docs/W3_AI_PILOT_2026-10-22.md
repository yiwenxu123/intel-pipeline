## 3. 指标与判定

| 指标 | 目标 | 说明 |
|---|---|---|
| 每周可用选题 | 8–10 条 | 人工判断“愿意写”，不是模型生成数 |
| precision@20 | >= 70% | 每周抽 20 条候选，编辑标可用/不可用 |
| AIHOT 独特选题 | >= 1 条/周 | 没有 AIHOT 就不会出现的选题 |
| AIHOT 占 Top20 | <= 50% | 防止单一信源挤掉 GitHub/Tavily |
| 编辑耗时 | <= 10 分钟/天 | 从打开到选出 3 条 |
| 采集成本 | 不增加付费源 | AIHOT 用公开 RSS，无 API key |

**保留 AIHOT 的条件**：连续两周满足 precision@20、至少 1 条独特选题/周、Top20 不被 AIHOT 主导。  
**移除 AIHOT 的条件**：连续两周 0 条独特选题，或编辑认为 AIHOT 条目“看起来多、能写的少”，或明显挤掉 GitHub/Tavily。  
**试点期间不做**：不写新采集引擎、不自动改评分、不自动发布。

## 4. 每日 / 每周动作

每日（约 5 分钟）：

1. 运行 `ai_pilot_summary.py`，把数字填进第 2 节。
2. 看 3 条选题，标 Usable；如果是 AIHOT 独有，标 Y。
3. 如果采集失败或 AIHOT 为 0，记录原因。

每周五（约 20 分钟）：

1. 抽 20 条候选，人工标可用/不可用，计算 precision@20。
2. 数本周 Usable 选题、AIHOT unique 选题。
3. 判断：继续 / 调整 source 权重 / 移除 AIHOT。
4. 更新本文件和 Q4 计划状态。

## 5. 风险与边界

- AIHOT 是外部公开 RSS，不是本项目代码；feed 变更/停用会影响采集。
- 旧域名 `aihot.virxact.com` 2026-10-31 停用；collector 已改用 `aihot.news`。
- 临时副本跑完整 collector 会写生产 Obsidian 路径；dry-run 必须禁用 `_sync_to_obsidian` 或改临时路径。10-22 已发生一次覆盖，已用生产 JSON 恢复。
- AIHOT 可能让 Top20 同质化；每日看 `AIHOT top20` 比例，超过 50% 就降权或减量。
- 试点结束前不根据“感觉”改 source 权重；用两周数据决定。
